# Skill: 規格紀錄

## 目的

維護一份清楚的 Markdown 作業規格紀錄，包含需求、決策、限制與交付項目。
當專案需求、資料集選擇、檔名、輸出格式或評分重點被討論或變更時，必須使用此 skill。

## 紀錄檔案

更新：

```text
.agent/records/SPEC.md
```

## 使用時機

任何涉及下列事項的工作前後，都要使用此 skill：

- 作業需求解讀。
- 資料集選擇。
- 特徵數量與目標變數決策。
- 模型範圍與必要分析項目。
- 報告架構。
- 繳交壓縮檔規劃。
- README 或最終交付項目規劃。

## 必要行為

1. 改變專案方向前，先讀取 `.agent/records/SPEC.md`。
2. 做出決策時，新增或更新精簡紀錄。
3. 除非明確取代舊決策，否則保留舊決策；若有取代，需標明日期與原因。
4. 連結、資料集名稱、檔名與評分要求必須保持精確。
5. 若需求尚不確定，寫入 `待確認問題`，不要默默猜測。
6. 所有 `.agent/records` 內的紀錄一律使用繁體中文；專有名詞、程式檔名、資料集名稱、指標縮寫與原始英文標題可保留英文。

## 必要章節

規格紀錄應包含：

- 作業摘要
- 資料集要求
- 已選資料集
- 目標變數
- 特徵規劃
- 建模要求
- 評估要求
- 報告要求
- 繳交檔案
- 決策紀錄
- 待確認問題

## 品質標準

紀錄必須清楚到讓另一個 agent 不需要重讀完整對話，也能接續完成作業。
